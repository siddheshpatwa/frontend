=====================================================================
A. SECURITY - fix before any deploy
=====================================================================

A1. [TESTED] AI endpoints have no login check
    POST /api/ai/suggest-name and /api/ai/generate-json returned 200 with no
    cookie. Anyone with the URL can spend the Gemini quota.
    Files: src/app/api/ai/suggest-name/route.ts, src/app/api/ai/generate-json/route.ts
    Fix: call auth.api.getSession in each route, return 401 if none.

A2. [CODE] Server actions do not check who is calling or who owns the data
    Files with no currentUser() check:
      src/modules/collections/action/index.ts  (create/get/edit/delete)
      src/modules/request/action/index.ts      (add/save/get/run/runDirect/sendRequest)
      src/modules/realtime/action/index.ts     (presets and messages)
    Any caller who knows an ID can read, edit or delete another user's
    collections, requests and presets.
    Also getAllWorkspaceMembers and getWorkspaceById return data for any ID
    (getAllWorkspaceMembers includes the full user record).
    Fix: check the session in every action and confirm the user is a member of
    the workspace that owns the record.

A3. [CODE] Anyone logged in can create invites for any workspace
    generateWorkspaceInvite only checks that a user is logged in, not that they
    belong to (or administer) the workspace. src/modules/invites/action/index.ts

A4. [TESTED] Send Request can reach internal addresses (SSRF)
    sendRequest made a server-side call to http://127.0.0.1:5433 (your Postgres).
    On a public host this can reach cloud metadata endpoints and private services.
    File: src/modules/request/action/index.ts (sendRequest)
    Fix: block private/loopback/link-local ranges, allow only http/https.

A5. [CODE] Server logs every response body
    console.log(res.data) in sendRequest prints full response bodies (can include
    tokens or personal data) to server logs. ~22 console.log calls across src/modules.

B. WILL BREAK IN PRODUCTION
=====================================================================

B1. [CODE] Auth client base URL is hardcoded to http://localhost:3000
    src/lib/auth-client.ts. Sign-in from a deployed site will call localhost.
    Fix: use NEXT_PUBLIC_APP_URL, or remove baseURL (same domain).

B2. [TESTED] NEXT_PUBLIC_APP_URL is missing from .env
    Invite links are built as `${process.env.NEXT_PUBLIC_APP_URL}/invite/...`
    and would start with "undefined". src/modules/invites/action/index.ts:23

B3. [CODE] OAuth callback URLs and BETTER_AUTH_URL only cover localhost
    Add the deployed callbacks (/api/auth/callback/google, /api/auth/callback/github)
    in both provider consoles and set BETTER_AUTH_URL to the deployed address.

B4. [TESTED] Node version
    Machine runs Node 20; a Prisma sub-package requires Node 22+. Use Node 22 on
    the deploy target.

=====================================================================
C. FUNCTIONAL BUGS
=====================================================================

C1. [TESTED] No request timeout
    A server that never answers leaves Send hanging forever (still pending after
    15 s in test). Add a timeout (e.g. 30 s) to the axios config in sendRequest.

C2. [CODE] Error message is lost when a request fails
    run() saves body = null when result.error is set, so the response viewer
    shows no reason (e.g. "connect ECONNREFUSED", "Invalid URL").
    Fix: store result.error in the run body / statusText.

C3. [TESTED] URLs without a scheme fail
    "example.com" returns "Invalid URL". Prepend https:// when the scheme is
    missing, or show a clear message.

C4. [CODE] PATCH cannot be chosen
    The database and types support PATCH, but the method dropdown in
    src/modules/request/components/request-bar.tsx only lists GET, POST, PUT,
    DELETE.

C5. [CODE] Send only works on saved requests
    RequestBar uses run(tab.requestId). An unsaved tab has no requestId, so the
    lookup fails and the user sees "Failed to send request." runDirect() exists in
    the action file but nothing uses it. Same behaviour as the reference repo.

C6. [TESTED] Wrong response size for text and empty bodies
    Size is computed from JSON.stringify(data), which adds quotes: "hello" (5 bytes)
    shows 7, an empty 204 shows 2. Use the raw byte length.

C7. [CODE] Failures are swallowed and return undefined
    collections actions (and several workspace actions) catch errors, only
    console.log them, and return undefined. The UI cannot show an error, and
    TanStack Query treats it as success.

C8. [CODE] Accepting an invite as an existing member throws
    acceptWorkspaceInvite creates the membership without checking one exists; the
    (userId, workspaceId) unique constraint then raises a raw database error.

C9. [CODE] currentUser() hides Next.js's "dynamic route" signal
    The try/catch also catches DYNAMIC_SERVER_USAGE, so production builds print
    an "Error fetching current user" stack trace. Harmless at runtime, but noisy.

C10. [CODE] Realtime presets/messages use onDelete: SetNull
    Deleting a workspace leaves orphaned presets and messages with a null
    workspaceId/presetId instead of removing them.
